# tg-bot-mydeepseek

Телеграм-бот на **DeepSeek API** (модель `deepseek-flash`). Работает в двух режимах:

- **Inline** — в любом чате наберите `@username ваш запрос`, бот вернёт ответ, который можно отправить в чат. Если в ответе есть ссылки на изображения, они показываются галереей — тапните, чтобы вставить картинку (по аналогии с `@pic`).
- **Личные сообщения и группы** — обычный диалог с ботом. Пришлите **фото** (или фото с подписью-вопросом, или ответьте на фото) — бот разберёт изображение. Ссылку на картинку можно указать и прямо в тексте запроса.
- **Сравнение картинок (`/cmp`)** — бот собирает интерактивный HTML-бабл Telegram: две картинки со шторкой «до/после» прямо в сообщении. Каждое сравнение получает номер, сжатые картинки остаются в кеше бота, а в любом чате можно набрать `@username #номер` и выбрать пункт **«Вставить превью»** — в чат вставится фото «до/после» с кнопкой «Открыть сравнение» под ним (шторка в inline — только при `CMP_INLINE_WIDGET=true`: бета Bot API отклоняет widget-контент в inline-выдаче).

Контекст диалога не сохраняется: каждый запрос независим. Режим рассуждений выключен по умолчанию и включается командой `/think`.

## Команды

| Команда | Действие |
| --- | --- |
| `/start` | Приветствие |
| `/help` | Справка |
| `/cmp` | Сравнить две картинки: альбом с подписью `/cmp` или две ссылки |
| `/think` | Включить/выключить режим рассуждений (для сложных задач) |
| `/reset` | Сбросить настройки |

## Требования

- Python 3.11+ (или Docker)
- Токен бота от [@BotFather](https://t.me/BotFather)
- Ключ DeepSeek API с [platform.deepseek.com](https://platform.deepseek.com) с положительным балансом

### Настройка бота в @BotFather

1. Создайте бота и получите токен: `/newbot`.
2. Включите inline-режим (обязательно!): `/setinline` → укажите подсказку, например `Поиск ответа…`.
3. Разрешите добавление в группы: `/setjoingroups` → **Enable**.
4. По желанию: `/setinlinefeedback` → статистика использования inline-режима.

> Юзернейм бота должен совпадать со значением `BOT_USERNAME` в `.env` — по нему бот понимает, когда его упомянули в группе. Значение `BOT_USERNAME` задаётся при развороте и обязательно к заполнению; можно писать как `name`, так и `@name`.

## Запуск

### 1. Что понадобится

- **Python 3.11+** (или Docker) — проверено на 3.12 и 3.14;
- **токен бота** от [@BotFather](https://t.me/BotFather);
- **ключ DeepSeek API** с положительным балансом;
- в @BotFather у бота включён **inline-режим** (`/setinline`) и разрешены группы
  (`/setjoingroups`), а его юзернейм совпадает с `BOT_USERNAME`;
- для `/cmp` — клиент Telegram **13.2+** (HTML-баблы). Если клиент старый или это группа,
  бот не падает: он пришлёт обе картинки альбомом и номер текстом.

### 2. Установка

```bash
git clone git@github.com:SowingSadness/tg-bot-mydeepseek.git
cd tg-bot-mydeepseek

python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows (PowerShell):
.venv\Scripts\Activate.ps1

pip install -r requirements.txt

cp .env.example .env      # Windows: copy .env.example .env
```

### 3. Настройка `.env`

Минимум, без которого бот не стартует:

```env
TELEGRAM_BOT_TOKEN=123456789:AAAA-ваш-токен
DEEPSEEK_API_KEY=sk-ваш-ключ
BOT_USERNAME=имя_бота_без_собаки
```

Для `/cmp` уже всё настроено по умолчанию, менять нужно только при желании:

```env
WIDGET_API_BASE=https://api.telegram.org/beta   # sendWidget из Bot API 10.4 пока на бете
CMP_CACHE_DIR=var/cmp                            # каталог SQLite-кеша; создаётся сам
```

Остальные переменные (лимиты, TTL кеша, подписи бабла) — в таблице
[«Сравнение картинок (`/cmp`)»](#сравнение-картинок-cmp) и в `.env.example`.

### 4. Запуск

```bash
python -m bot.main
```

Запускать **из корня репозитория** (иначе `No module named bot`). Бот работает на long polling,
меню команд (`/start`, `/help`, `/cmp`, `/think`, `/reset`) регистрируется сам при старте,
остановка — `Ctrl+C`. При старте пишутся строки вида:

```
Бот @имя_бота запущен (модель deepseek-flash, BOT_USERNAME=имя_бота)
Кеш сравнений: var/cmp/cmp.db (удалено 0, осталось 0)
```

Это уровень `INFO`, а по умолчанию в `LOG_LEVEL` стоит `ERROR` — чтобы увидеть эти строки,
поставьте `LOG_LEVEL=INFO` или `LOG_LEVEL=DEBUG` (см. [«Логи и отладка»](#логи-и-отладка)).

Другие способы запуска: [Docker](#деплой-на-vps-debian-через-docker) и
[systemd без Docker](#деплой-без-docker-systemd).

### 5. Проверка, что всё работает

1. `/start` в личке — приходит приветствие с кнопкой «Рассуждения».
2. Любой вопрос текстом — приходит ответ DeepSeek.
3. `@имя_бота погода в Лиссабоне` в любом чате — появляется inline-выдача.
4. `/cmp` → пришлите два фото одним альбомом с подписью `/cmp` → в чате бабл со шторкой «до/после».
   Подпись — две строки: `Номер сравнения:` и `@имя_бота #482913`; следом подсказка про inline,
   тоже двумя строками (`Номер сравнения: #482913` и `@имя_бота #482913`).
5. `@имя_бота #482913` в другом чате — выберите **«Вставить превью»**: в чат вставится фото
   «до/после» с кнопкой «Открыть сравнение» (то же можно сделать отдельным пунктом
   «Открыть сравнение»; шторка — только при `CMP_INLINE_WIDGET=true`).
6. `ls var/cmp` — там `cmp.db` (в Docker — том `cmp-cache`).

### Если что-то не работает

| Симптом | Причина | Что делать |
| --- | --- | --- |
| `ValidationError ... Field required` при старте | в `.env` нет обязательных переменных | заполнить `TELEGRAM_BOT_TOKEN`, `DEEPSEEK_API_KEY`, `BOT_USERNAME` |
| `No module named bot` | запуск не из корня репозитория | `cd` в корень, затем `python -m bot.main` |
| `401 Unauthorized` / бот не отвечает | неверный токен или бот заблокирован | проверить токен, `/start` у бота |
| inline ничего не показывает | у бота не включён `/setinline` | включить в @BotFather и перезапустить бота |
| inline отвечает «Не успеваю за лимит» | DeepSeek медленнее дедлайна | уменьшить `INLINE_MAX_TOKENS`, проверить `INLINE_TIMEOUT` |
| `/cmp`: «Клиент не принял виджет» | клиент < 13.2, группа/канал или `WIDGET_API_BASE` не бета | обновить клиент, писать в личку, проверить `WIDGET_API_BASE`; картинки всё равно придут альбомом |
| `/cmp`: «не удалось скачать по ссылке» | ссылка недоступна, не картинка, больше `CMP_MAX_BYTES` или приватный адрес | дать прямую ссылку на файл, поднять `CMP_MAX_BYTES`, `CMP_ALLOW_PRIVATE_HOSTS=true` только для своих |
| `@бот #482913` → «не найдено» | номер чужой (`CMP_SHARE_BY_ID=false`), истёк TTL или другой `CMP_CACHE_DIR` | делать сравнение в своём чате, поднять `CMP_CACHE_TTL_DAYS`, не менять каталог кеша |
| `Permission denied: /app/var/cmp` в Docker | образ собран до появления каталога кеша | пересобрать: `docker compose up -d --build` |
| Бот молчит в группе | нет упоминания `@username` или `BOT_USERNAME` не совпадает | упомянуть бота, проверить предупреждение в логе о `BOT_USERNAME` |

## Логи и отладка

Уровень логов берётся из переменной `LOG_LEVEL` и по умолчанию равен **`ERROR`** — в лог
попадают только ошибки. Информационные строки («Бот … запущен», «Кеш сравнений: …», замеры
inline) при этом **не печатаются**: это осознанно, чтобы не шуметь в проде.

Включить подробный лог:

```env
# .env
LOG_LEVEL=DEBUG
```

```bash
# Docker: разово, без правки .env и compose-файла
docker run -e LOG_LEVEL=DEBUG …

# Docker Compose: переменная окружения у сервиса либо перед командой
LOG_LEVEL=DEBUG docker compose up -d
```

`INFO` — то же, что и раньше: старт, чистка кеша и замеры inline-ответов, но без вызовов
API. `DEBUG` дополнительно пишет:

- **вызовы Bot API** — одной строкой, без тела запроса:
  `api sendWidget chat_id=123 html=3120chars …`, `api answerInlineQuery results=3 …`
  (HTML-бабл и base64-картинки заменены на `<N>chars`);
- **ответы Bot API** — `ok`/`err`, `http=`, `error_code=`, `description=` и краткий итог
  (`message_id=…`, `results=…`, `widget_id=…`); паузы по `retry_after` пишутся на `WARNING`,
  финальная ошибка — на `ERROR`;
- **входящие сообщения и inline-запросы** — `update=message chat_id=… chat_type=private
  user_id=… text='…'`; текст и подпись обрезаются до 120 символов, для фото/документа
  печатаются `file_id`, размеры и `media_group_id`.

**Токен бота и base64-картинки в лог не попадают**: они вырезаются (`<token>`,
`data:image/webp;12345chars`) на любом уровне, включая `DEBUG`. А вот тексты сообщений
пользователей и их id при `DEBUG` видны — не включайте подробный лог на общем боте без
необходимости.

### Как ускоряется inline-ответ

Inline-режим самый чувствительный к задержке: Telegram аннулирует inline-запрос
примерно через 10 секунд (`QUERY_ID_INVALID`). Что сделано для скорости:

- **прогрессивный ответ**: ответ стримится из DeepSeek, и частичный текст показывается
  сразу (`INLINE_EARLY_UPDATE`) — первую версию ответа видно за секунды, а не за 10;
  когда генерация завершается, выдача обновляется полным текстом и картинками
  (повторный `answerInlineQuery` по тому же `query_id` заменяет результаты);
- ответ ограничен по длине (`INLINE_MAX_TOKENS`) и коротким системным промптом;
- thinking-режим в inline принудительно выключен — он не влезает в дедлайн;
- устаревшие запросы отменяются: пока вы печатаете, обрабатывается только последний;
- жёсткий дедлайн `INLINE_TIMEOUT`: если время вышло, отдаётся то, что успело
  сгенерироваться, иначе — подсказка с кнопкой «Открыть чат с ботом»;
- запросы короче 3 символов не отправляются в DeepSeek;
- ответы кэшируются в памяти бота и в кэше Telegram (`INLINE_CACHE_TTL`) — повторный
  тот же запрос отдаётся мгновенно и бесплатно;
- в выдаче не более 4 картинок и **только JPEG**: превью в PNG/WebP Telegram молча
  не показывает, а каждая картинка — это ещё и загрузка превью клиентом;
- соединение с DeepSeek прогревается при старте (TLS-хендшейк не попадает в первый запрос).

### Замеры в логах

Каждый inline-запрос пишет строку вида:

```
inline[abcdef12] user=123: ok ttft=0.87s early=1.24s total=3.10s chars=412 photos=0
```

- `ttft` — время до первого токена DeepSeek;
- `early` — когда показан частичный ответ (`-1`, если не показывался);
- `total` — полное время;
- `chars` / `photos` — длина ответа и число картинок в выдаче.

Другие варианты исхода: `cache_hit` (отдали из памяти), `deadline_partial`
(время вышло, отдали частичный), `deadline_empty` (не успел ни один токен),
`empty` (модель вернула пустой ответ), `error`. Ответы в личке/группах логируются
строкой `chat user=...: total=... chars=... images=... thinking=...`. Это уровень `INFO`:
при дефолтном `ERROR` замеров не видно — включайте `LOG_LEVEL=INFO` или `DEBUG`
(см. [«Логи и отладка»](#логи-и-отладка)).

### Как узнать свой Telegram ID

Напишите боту [@userinfobot](https://t.me/userinfobot) — он пришлёт ваш ID. Рекомендуется заполнить `ALLOWED_USER_IDS`, чтобы ботом не пользовались посторонние за ваш счёт.

## Сравнение картинок (`/cmp`)

Две картинки превращаются в **HTML-бабл** (Bot API 10.4, `sendWidget`) — картинку со шторкой
«до/после», которую можно тянуть пальцем прямо в сообщении.

1. Прикрепите два фото **одним альбомом** и подпишите `/cmp` — бот дождётся обеих картинок
   (дебаунс `CMP_ALBUM_WAIT`, по умолчанию 0.9 с) и сразу соберёт бабл. Или сразу ссылками:
   `/cmp https://a.jpg https://b.jpg`.
2. Если картинка одна, бот ответит «Нужны две картинки…» и ничего не запомнит: последовательного
   режима («пришлите вторую») больше нет.
3. Картинки обрезаются **одним и тем же окном под 3:2**, сжимаются в WebP и запекаются в HTML.
   Сборка сама подбирает ширину и качество (для каждой картинки — своё), чтобы уложиться в лимиты
   Telegram: 32 768 байт HTML и 4096 байт после `zlib` уровня 9.
4. Сравнение получает номер (`#482913`) — он в подписи сообщения, а **сжатые картинки** остаются
   в SQLite-кеше на диске (`CMP_CACHE_DIR`). Подпись — две строки, `@бот #номер` всегда
   на отдельной строке (шаблон — `CMP_CAPTION`, доступны `{id}`, `{a}`, `{b}`, `{bot}`):

   ```
   Номер сравнения:
   @sowing_tg_bot #482913
   ```

   Следом приходит подсказка-напоминание про inline, тоже двумя строками
   (`Номер сравнения: #482913` и `@sowing_tg_bot #482913`); её выключает `CMP_SHOW_HINT`.
5. В любом чате: `@username #482913` — выдача собирается из кеша: без DeepSeek, без
   скачиваний и без риска не уложиться в 10-секундный дедлайн inline-режима. Пункт
   **«Вставить превью»** вставляет в чат фото «до/после» — большой композит с подписью
   «Сравнение #482913 · До / После», а под ним висит кнопка **«Открыть сравнение»**
   (кнопка прикреплена к самому фото-результату). Фото — одна сцена 3:2: левая половина —
   левые 50% кадра «До», правая — правые 50% кадра «После», разделитель по центру, подписи
   «До»/«После» в верхних углах. Ширина `CMP_PREVIEW_WIDTH` (по умолчанию 2560 px, при 3:2
   композит 2560×1707 — Telegram ужмёт сам). Оба кадра режутся тем же окном 3:2, что и слои
   бабла, в композит идут только половины.

   В выдаче также есть:
   - **«Открыть сравнение»** — отдельный пункт: текстовое сообщение с той же url-кнопкой;
   - **шторка** — прежний HTML-бабл из кеша (клиенты 13.2+), **только при**
     `CMP_INLINE_WIDGET=true`: бета Bot API отклоняет widget-контент в inline
     (`INPUT_MEDIA_WIDGET_NOT_ALLOWED`), поэтому по умолчанию её нет. Если флаг включён,
     а сервер всё равно отказал, бот повторяет ответ без шторки — фото и кнопка
     остаются;
   - **текстовый фолбэк** — только когда показать больше нечего (нет ни превью, ни кнопки):
     сообщение с заголовком «Сравнение #482913 · только текст» и причиной (мини-апп не
     настроен, превью нет). В обычной выдаче текстового пункта нет.
6. Оговорки к inline-выдаче:
   - фото-превью есть только у сравнений, сделанных после обновления: у старых номеров
     `preview_file_id` не сохранён, поэтому выдача начинается с пункта «Открыть сравнение»;
   - кнопка «Открыть сравнение» появляется, когда задан `BOT_USERNAME`, а мини-апп в
     @BotFather настроен — как **Main Mini App** или как отдельное приложение через
     `/newapp`. Форма ссылки в кнопке зависит от `CMP_WEBAPP_SHORT_NAME`:
     - пусто → **Main Mini App**: `https://t.me/<бот>?startapp=<номер>_<подпись>`;
     - задан → отдельное приложение: `https://t.me/<бот>/<short_name>?startapp=<номер>_<подпись>`.
     Это нормальная конфигурация, а не ошибка: бот пишет фактическую форму ссылки в лог
     при старте (`Кнопка мини-аппа: …`);
   - превью хранится в кеше Telegram (`file_id`), поэтому при создании сравнения в **личке**
     на мгновение появляется служебное сообщение с фото, которое бот сразу удаляет, — это
     ожидаемо и не является багом;
   - `sendWidget` серверу в группы отправлять нельзя, поэтому в групповом чате бабл сам
     не появится — в чат уходит то, что вы выбрали в inline-выдаче (фото-превью или сообщение
     с кнопкой).
7. Если клиент не умеет виджеты, бот пришлёт обе картинки альбомом и номер текстом.

Кеш чистится по TTL и по числу записей (на старте и раз в 6 часов). Номер по умолчанию работает
только у своего владельца (`CMP_SHARE_BY_ID=false`), а не у любого, кто его подобрал.

### Качество превью и бюджет 4 КБ

Telegram принимает HTML-бабл, только если после `zlib` уровня 9 он весит **не больше 4096 байт** —
и это вместе с шаблоном, скриптом шторки и двумя `data:`-картинками. После минификации шаблон
занимает **~1117 байт** (было ~1369), остальное делят две картинки.

Замеры на реальной паре (2542×954 и 1100×704, общее окно 3:2):

| Ширина | `zlib` итога | Влезает в 4 КБ |
| --- | --- | --- |
| 430 px | 13.3 КБ | нет |
| 348 px | 10.1 КБ | нет |
| 281 px | 7.7 КБ | нет |
| 226 px | 5.9 КБ | нет |
| 182 px | 4.1 КБ | почти |
| 163 px | ~4.0 КБ | да |

Сборщик перебирает ширины и качества по метрике искажения (средняя абсолютная разница до/после
кодирования) и на такой паре выбирает **~163–182 px при q12–14** (`err_a≈0.025`, `err_b≈0.04–0.05`).
Вывод честный: две фотографии в 4 КБ — это **превью**, а не полноценные картинки. Детали смотрите
в оригиналах — они остаются в чате (фолбэком бот и так присылает обе картинки и номер текстом).

Рекомендации по исходникам:

- одна и та же сцена, кадр **3:2** (например 1800×1200) — тогда общее окно кропа не режет лишнего;
- **до 2000 px по длинной стороне**: больше бот всё равно уменьшит, а скачивание будет медленнее;
- **скриншоты — PNG** (текст и графика сжимаются квантованием заметно лучше), **фото — JPEG/PNG**.

## Локальная демка бабла

Посмотреть бабл из своих файлов в «телефоне», не отправляя его боту:

```bash
.venv\Scripts\python.exe -m bot.compare.demo --a D:/Pictures/1.png --b D:/Pictures/1.3.png
```

В Linux/macOS — то же с `python -m bot.compare.demo …`. В каталоге `--out` (по умолчанию
`out/demo`) появятся два файла:

- `widget.html` — **ровно тот** HTML, который уходит в `sendWidget`: без мока и без обёрток;
- `index.html` — страница-«телефон»: слайдер ширины бабла 200–600 px, переключатель
  тёмной/светлой темы, кнопка «перезагрузить», iframe с виджетом и подпись с размерами
  (`430px · zlib 3283/4096 · q34/34 · lossy/lossy`) и ошибками кодирования.

Полезные флаги: `--labels "До|После"`, `--width 430` (стартовая ширина превью), `--out`, `--open`.

На Windows есть обёртка `cmp-demo.cmd`: перетащите на неё два файла или запустите
`cmp-demo.cmd "D:\Pictures\1.png" "D:\Pictures\1.3.png" [ширина] [serve|build]` —
она сама найдёт `.venv`, поднимет демку и откроет браузер (`build` — только собрать файлы).
В консоль печатаются `width`, `quality_a/quality_b`, `profile_a/profile_b`, `zlib` (отдельно
примерный вклад шаблона и картинок), `raw`, `pictures` и `err_a/err_b`.

### Зачем нужен сервер

По умолчанию (`--no-server` или без `--serve`) `index.html` самодостаточен: виджет лежит
в `iframe srcdoc`, страницу можно открыть двойным кликом. Но на `file://` у iframe
непрозрачный origin, и `localStorage` в виджете бросает — положение шторки не запоминается.
Поэтому для полноценной проверки запускайте с сервером:

```bash
.venv\Scripts\python.exe -m bot.compare.demo --a … --b … --serve --open
```

Мини-сервер на `http.server` раздаёт каталог `--out`: `/` — страница, `/widget.html` — тот же
виджет с инжектированным перед ним мок-`TelegramWidget` (same-origin, поэтому `localStorage`
работает). Порт по умолчанию `8765`; если он занят, берётся следующий свободный — но только
когда `--port` не задан явно. Остановить — **Ctrl+C** (адрес и подсказка печатаются при старте).

Виджет получает мок `TelegramWidget` (`themeParams`, `colorScheme`, `ready`, `onEvent`,
`HapticFeedback`, `contentSafeAreaInset`, `request` → `console.log`) и CSS-переменные
`--tg-theme-*`, как в клиенте. Мок **не заменяет нативный рендерер** Telegram: именно в нём
и проявлялся баг с якорем левой картинки, поэтому финальную проверку всё равно стоит делать
отправкой бабла боту.

Геометрия слоёв задаётся в пикселях через JS (`getBoundingClientRect()` → `style.width/height`),
потому что клиенты Telegram не выводят ширину картинки из пропорций; окончательная проверка —
на живом клиенте, демка нативный движок не воспроизводит.

## Мини-апп сравнения (`/app/cmp`)

Полноэкранное сравнение в **полном разрешении**: шторка «до/после» на canvas, зум и панорама
пальцем. Открывается кнопкой **«Открыть сравнение»** в inline-выдаче (`@бот #номер`) или прямой
ссылкой. Форма ссылки зависит от `CMP_WEBAPP_SHORT_NAME`:

- **пусто** → **Main Mini App**: `https://t.me/<бот>?startapp=<id>_<sig>` — это валидная
  конфигурация, если мини-апп бота назначен главным в @BotFather;
- **задан** → отдельное приложение: `https://t.me/<бот>/<short_name>?startapp=<id>_<sig>`.

Кнопка появляется, когда задан `BOT_USERNAME`; фактическая форма ссылки пишется в лог при
старте (`Кнопка мини-аппа: …`). `CMP_WEBAPP_PORT` включает только HTTP-сервер мини-аппа и на
наличие кнопки не влияет.

### Эндпоинты

| Метод и путь | Что отдаёт |
| --- | --- |
| `GET /app/cmp` | Страница мини-аппа: один HTML, CSS и JS внутри, без внешних скриптов и сборки |
| `GET /api/cmp/<token>` | JSON `{id, labels, aspect, width, height, images:{a,b}}`; `Cache-Control: no-store` |
| `GET /app/cmp/img/<token>/<a\|b>` | Оригинал в полном разрешении: **AVIF** при `Accept: image/avif`, иначе **WebP**; `Vary: Accept`, `ETag`, `Cache-Control: immutable`, `If-None-Match` → 304 |
| `GET /healthz` | `ok` — для проверок systemd и проб балансировщика |

В JSON `/api/cmp/<token>` поля `width`/`height` — это размеры слоя бабла из кеша (например
430×287): они нужны только для пропорций; полное разрешение страница берёт из самих картинок
(`naturalWidth`/`naturalHeight`).

### Включение

```bash
# .env
CMP_WEBAPP_PORT=8081            # 0 = сервер выключен (поведение как раньше)
CMP_WEBAPP_HOST=127.0.0.1       # systemd/nginx; в Docker — 0.0.0.0
CMP_WEBAPP_PUBLIC_URL=https://example.com/app/cmp   # для логов и документации
CMP_WEBAPP_AUTH_TTL=86400       # сколько живёт initData, секунды
CMP_ORIGINALS_WIDTH=1600        # ширина оригиналов для мини-аппа, px
CMP_WEBAPP_SHORT_NAME=cmp       # short name мини-аппа; пусто = Main Mini App (t.me/<бот>?startapp=…)
```

1. Сервер поднимается в том же процессе, что и бот (`bot/main.py`), и гаснет вместе с ним;
   при `CMP_WEBAPP_PORT=0` сокет не создаётся вообще. Порт `8081` — только внутри, TLS снаружи.
2. В @BotFather выберите один из двух вариантов:
   - **Main Mini App**: `/myapps` → выбрать приложение → **Edit** → назначить его главным
     (Main Mini App) с Web App URL `https://<домен>/app/cmp`; `CMP_WEBAPP_SHORT_NAME` оставьте
     пустым — кнопка будет вести на `https://t.me/<бот>?startapp=…`;
   - **отдельное приложение**: `/newapp` → выбрать бота → name, description, фото → **Web App
     URL** `https://<домен>/app/cmp`; short name из ответа BotFather — в `CMP_WEBAPP_SHORT_NAME`,
     тогда кнопка ведёт на `https://t.me/<бот>/<short>?startapp=…`.
   После этого в inline-выдаче появляется кнопка «Открыть сравнение» у фото-превью и отдельного
   пункта. Превью хранится в кеше Telegram (`file_id`), поэтому при создании сравнения в личке
   на мгновение появляется служебное сообщение — это ожидаемо.
3. Оригиналы сохраняются при каждом `/cmp` (WebP всегда, AVIF — если Pillow умеет AVIF)
   и лежат рядом с кешем в `CMP_CACHE_DIR/originals`.

### TLS и прокси

Telegram открывает Mini Apps **только по HTTPS**, поэтому наружу нужен nginx (или Caddy)
с сертификатом и `proxy_pass` на loopback-порт бота:

```nginx
server {
    listen 443 ssl;
    server_name example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    location /app/cmp/img/ {          # оригиналы (AVIF/WebP)
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
    }
    location /api/cmp/ {              # JSON с данными сравнения
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
    }
    location /app/cmp {               # сама страница
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
    }
}
```

Длиннейший префикс побеждает, поэтому `/app/cmp/img/` уходит в свой `location` раньше, чем
`/app/cmp`. В Docker порт проброшен как `127.0.0.1:8081:8081`, а `CMP_WEBAPP_HOST=0.0.0.0` —
снаружи контейнера он всё равно доступен только через прокси.

### Безопасность

- `startapp`-токен (`<id>_<sig>`, ≤64 символов base64url) — это **capability**: подпись
  HMAC-SHA256 от токена бота и номера. Кто знает ссылку, тот может посмотреть картинки
  по ней — поэтому ссылку не пересылайте в публичные чаты.
- `/api/cmp/<token>` дополнительно требует валидный `initData` (HMAC по алгоритму Bot API,
  свежесть `auth_date` ≤ `CMP_WEBAPP_AUTH_TTL`) и совпадение владельца: чужой номер отдаёт
  `403`, пока не включён `CMP_SHARE_BY_ID=true`. Без `initData` — `401`.
- Картинки `/app/cmp/img/...` отдаются по токену (страница грузит их напрямую), поэтому
  подпись проверяется и там: битая — `403`, неизвестная сторона — `404`, path traversal
  невозможен (в пути только `a`/`b`).
- Access log aiohttp отключён (`access_log=None`): токен из URL не попадает в логи.
  Токен бота и `initData` не логируются никогда.

### Ограничения

- Старые сравнения (сделанные до обновления) оригиналов не имеют: мини-апп покажет
  «ссылка устарела или сравнение удалено из кеша» — такое сравнение надо сделать заново.
- Оригиналы чистятся вместе с записью кеша — по TTL (`CMP_CACHE_TTL_DAYS`) и по лимиту
  записей (`CMP_CACHE_MAX_ENTRIES`); отдельного хранилища у мини-аппа нет.
- AVIF кодируется на CPU (доли секунды на кадр) в отдельном потоке и не задерживает `/cmp`;
  если Pillow собран без AVIF — остаётся WebP, страница работает так же.

## Как это работает

- Запросы идут на OpenAI-совместимый эндпоинт DeepSeek (`/chat/completions`).
- Изображения передаются как base64 data-URL (скачанные из Telegram фото) или как внешние `http(s)`-ссылки из текста запроса.
- Режим рассуждений управляется параметром `thinking` (`extra_body`), при включении добавляется `reasoning_effort: high`.
- Inline-запросы Telegram ограничены 256 символами и не могут нести изображение — для картинок используйте личку или группу.
- В группах бот отвечает только на упоминание `@username` или на ответ (reply) своему сообщению.
- `/cmp` собирает HTML-бабл из двух WebP и отправляет его через `sendWidget` (Bot API 10.4, пока на
  бете). Номер сравнения, сжатые картинки и `preview_file_id` композита хранятся в
  SQLite-кеше, поэтому inline по `#номер` отдаёт фото-превью, кнопку и текст
  за миллисекунды.

## Ограничения

- DeepSeek **не генерирует** изображения — бот только анализирует присланные картинки и умеет вставлять ссылки на изображения, если они есть в ответе модели.
- Telegram Bot API даёт скачивать файлы до 20 МБ, поэтому очень большие фото бот не обработает.
- Ответы длиннее 4096 символов разбиваются на несколько сообщений.
- `/cmp` работает в личных сообщениях: в каналы виджеты отправлять нельзя, а в группах бот
  отвечает только на упоминание.
- Внутри бабла — только сжатые превью, оригиналы остаются в чате обычными фото.
- HTML-баблы требуют клиента Telegram 13.2+ и бетового Bot API: старые клиенты покажут заглушку
  или присланный альбом.
